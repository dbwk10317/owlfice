# Owlfice 동작 계약

구현된 동작은 코드와 fixture를 기준으로 하며, 아래의 **목표**, **미확인**, **현재 한계**를 보장으로 읽지 않는다. 설치·실행·검증 명령은 [BUILD](BUILD.md), 화면 표현과 수동 검수는 [HANDOFF](../design/HANDOFF.md), 작업 규칙은 [AGENTS](../AGENTS.md)에 둔다.

<a id="c1"></a>

## C1. 지원 범위와 읽기 전용

화면 이름은 야근불 · Owlfice다. 현재 탐색·파서는 이 PC의 Windows와 실행 중인 WSL에 있는 Claude Code 계열과 Codex 계열의 로컬 기록을 다룬다. SSH·다른 PC·클라우드의 기록은 수집하지 않는다. 다른 제품의 이름이나 열거형이 코드에 있다는 이유로 지원을 확정하지 않는다. 실제 입력 범위는 [탐색](../src-tauri/src/discover/windows.rs), [파서](../src-tauri/src/parse/mod.rs), [fixture 출처](../fixtures/README.md)가 기준이다.

에이전트를 조종하거나 원본 세션·설정·저장소 파일을 쓰지 않는다. 앱 자신의 설정·진단 파일은 별도 관리한다. 꺼진 WSL을 실행하지 않으며 파일 접근 조건은 C5를 따른다. 과거 세션을 재생하는 제품 기능은 현재 범위 밖이다. 앱은 수집 자료를 외부 서버로 보내거나 서버 포트를 열지 않는다. 사용자가 PR 링크를 누르면 검증된 HTTPS 주소를 기본 브라우저로 연다. [주소 검증과 열기](../src-tauri/src/detail.rs)

<a id="c2"></a>

## C2. 회사·팀·직원과 신뢰도

팀은 세션 하나와 그 메인·서브에이전트다. 같은 세션 문자열이라도 호스트·제품이 다르면 다른 팀이다. 직원은 소속 팀과 함께 식별한다. 규모에 따라 팀별 사무실 또는 제품별 합동 사무실로 배치하지만 팀의 활동 기록은 합치지 않는다. 실제 식별키와 사무실 매핑은 [world](../src-tauri/src/office/world.rs), 직급·담당·이름 규칙은 [classify](../src-tauri/src/office/classify.rs)와 [names](../src-tauri/src/office/names.rs)가 기준이다.

기록에 명시된 사실은 확인됨, 침묵·시간·문장 패턴으로 판단한 것은 추정으로 취급한다. 추정을 성공·확정 장애로 승격하지 않으며 화면에서 추정임을 드러낸다. 허가 대기와 진행 중 도구는 기본 자세보다 앞서며, 팀의 졸음·퇴근과 직원 상태의 판정은 [classify](../src-tauri/src/office/classify.rs)를 따른다. 출근은 별도 연출이다. 활동 시각은 이벤트 기록을 사용하고, 파일 수정 시각은 읽기 필요 여부를 판단하는 신호로만 쓴다.

계획 진행(`planning`)은 직원별로 보존한다. 계획 진입·종료 호출을 일반 질문과 구별하고, 종료는 그 호출에 대응하는 결과로 판단한다. 리뷰 문장의 승인 추정이나 다른 질문의 답으로 계획을 끝내지 않는다. 계획 종료 질문을 기다리는 동안에도 계획 상태는 유지하지만 허가 대기 자리가 우선한다. 장애·퇴근은 회의실 연출만 중단하고 계획 상태를 지우지 않는다. (미확인) 실제 계획 진입·종료 연쇄는 아직 fixture로 확인되지 않았으며 Codex 동등 신호도 확인되지 않았다. 지원 신호와 방별 조건은 [HANDOFF 5절](../design/HANDOFF.md#5-상태--화면-대응)에 둔다.

자료실·경비실 방문은 업무 상태가 아닌 일회성 연출이다. 옥상은 S58 휴식 대상에게 탕비실 자리가 부족할 때 쓰는 둘째 자리이며 별도 대기 상태를 만들지 않는다. 근속과 커피 잔의 경과 기준은 해당 직원의 입사 시각이다.

## C3. 선택과 사용자에게 보이는 상태

사무실 선택은 표시 대상을 바꾸며 다른 팀의 수집·상태 갱신을 멈추지 않는다. 합동 사무실의 팀 선택은 해당 팀을 강조하고 패널의 팀을 맞춘다. 직원·카드와 세션 진입점은 같은 상세 정보를 가리킨다. 카드와 최근 활동의 식별에는 팀까지 포함한다. 근태는 상태에서 계산하며 외근·외출·퇴근을 서로 다른 의미로 유지한다. 정렬·분류의 실제 규칙은 [우측 패널](../src/sidebar-right.ts), [ticker](../src/ticker.ts), [renderer](../src/office/renderer.ts)에 둔다.

우측 패널의 "퇴근한 세션 표시"는 기본 켬이다. 끄면 팀 상태가 `Off`인 세션만 패널에서 숨기며 졸음·대기 세션은 유지한다. 수집·좌측 목록·캔버스 상태에는 영향을 주지 않는다. 표시 선택은 실행 중 사무실·규모 전환에도 유지하지만 앱 재시작을 위해 저장하지 않는다.

목록을 아직 받지 못한 상태와 확정된 빈 목록은 다르다. 빈 목록에서 탐색 후보가 아직 없으면 준비 중, 발견한 기록 루트가 있으면 모두 퇴근, 발견하지 못했으면 후보 경로와 결과·직접 지정 동작을 보여 준다. 빈 상태의 탐색 정보는 메모리 조회로 갱신하며 사무실이 생긴 뒤 늦은 응답이 덮지 못한다. 시작 실패는 안내와 사용자의 재시도 동작으로 드러낸다. [빈 상태](../src/empty-office.ts), [기동](../src/main.ts)

화면 요약의 결재 대기 수는 허가 응답 대기(S34)를 센다. OS 알림 대상은 일반 사용자 응답 대기(S32)도 포함한다.

OS 알림은 설정이 켜져 있고 직원별 결재 대기 구간이 30초 이상 지났으며 알림 시점에 창이 숨겨져 있을 때 해당 직원의 대기 구간당 한 번 보낸다. 명령·지시 원문을 알림에 넣지 않는다. 소리의 별도 경계는 C10을 따른다. [알림 판정](../src-tauri/src/notification.rs)

## C4. 기동·재구성과 순서

이벤트를 먼저 구독하고 초기 스냅샷을 받는다. 초기화 중 도착한 갱신도 잃지 않는다. 목록 순번과 사무실별 상태 순번은 독립적이며, 같은 스트림의 오래된 순번만 버린다. 스냅샷보다 최신인 버퍼를 뒤로 되돌리지 않는다. 모든 활성 팀의 상태를 유지하고 선택된 사무실의 전체 상태를 내보낸다. [IPC](../src-tauri/src/ipc.rs), [프론트 저장소](../src/store.ts)

파일 I/O·파싱은 공유 사무실 잠금 밖에서 수행한다. 호스트별 작업을 분리해 한 호스트의 지연이 다른 호스트를 막지 않게 한다. 파일 내 순서를 보존하면서 논리 시각으로 병합하고, 같은 시각의 순서와 시각 누락 처리도 결정적이어야 한다. 서브에이전트는 이벤트 적용 전에 등록한다. 팀의 어느 파일이 재설정을 요구해도 팀 전체를 재구성한 뒤 한 번에 교체한다. 재구성에서는 과거 사건의 연출을 되살리지 않되, 막 시작한 새 팀의 출근 예외는 유지한다. [스케줄러](../src-tauri/src/tail/scheduler.rs), [런타임](../src-tauri/src/runtime.rs)

## C5. 탐색과 WSL 접근 금지

자동 탐색과 수동 루트는 같은 접근 판정과 중복 제거를 거친다. 수동 루트는 Claude의 projects 또는 Codex의 sessions 자체를 지정한다. Windows 경로의 대소문자·구분자와 WSL 공유 별칭은 정규화하되 WSL 내부 경로의 대소문자는 보존한다. 환경변수의 확장 UNC 경로도 WSL 판정을 우회하지 못한다. 형식 검증을 위해 파일을 열지 않는다. [탐색 통합](../src-tauri/src/discover/mod.rs), [설정 검증](../src-tauri/src/settings.rs)

입력 대상은 로컬 Windows 경로와 WSL UNC 경로다. 드라이브 경로는 로컬 장치 매핑이 확인될 때만 열며, 확인되지 않은 매핑 드라이브는 존재 확인 없이 `Unknown`으로 남긴다. [Windows 경로 판정](../src-tauri/src/discover/windows.rs)

등록된 WSL 배포판이 실행 중임을 명시적으로 확인한 경우에만 UNC를 읽는다. 꺼짐·판정 불가·알 수 없는 수동 배포판에는 존재 확인조차 하지 않는다. 홈을 알아내기 위해 꺼진 공유를 읽지 않으며 경로 미확인을 허용한다. 알려지지 않은 수동 경로는 입력을 후보로만 남긴다. 루트가 없다는 결과와 접근하지 않았다는 결과를 구분한다. 홈 탐색은 기본 사용자 기준이며 로그인 셸이나 가상 디스크 직접 읽기를 사용하지 않는다. [WSL 탐색](../src-tauri/src/discover/wsl.rs)

WSL 디렉터리 스캔은 실행 상태 확인에 묶는다. 응답 지연으로 의심 상태가 된 호스트에는 추가 UNC 접근을 시작하지 않는다. 작업 상태·미커밋 위치는 보존하되 화면에서는 추정 퇴근으로 표시하고 자리를 비운다. 정상 연결에서 밀린 읽기를 반영한 뒤 재직 표시와 자리를 복구한다. **현재 한계:** 실행 상태 확인과 다음 접근 사이에 배포판이 종료될 수 있고, 진행 중인 OS I/O를 취소할 수 없다. 핸들 닫기까지 실행 상태를 고려하는 이유다. 홈을 이미 찾았을 때 환경변수로 재정의하지 않는 제한 등은 [구현 주석](../src-tauri/src/discover/wsl.rs)에 둔다.

## C6. 증분 읽기와 폴링

완성된 줄만 파싱하고 마지막 미완성 줄은 다음 읽기까지 보관한다. 읽기 위치는 상태 적용이 끝난 뒤 커밋한다. 파일 축소·교체·경계 불일치는 재설정으로 처리하며, 읽기 실패를 빈 파일이나 세션 삭제로 해석하지 않는다. 읽기·줄 크기 상한과 재설정 조건은 [TailReader](../src-tauri/src/tail/mod.rs)가 기준이다. **현재 한계:** 경계 해시는 파일 전체 변경 검출기가 아니므로 검사 경계보다 앞선 임의 수정까지 검출한다고 보장하지 않는다.

처음 발견한 파일은 전체 재구성하되 최근 시작한 팀만 출근 연출을 한다. 신규 파일 스캔, 호스트 상태 확인, 선택·비선택·퇴근 팀 폴링은 목적에 따라 주기를 나눈다. 연속된 정상 스캔에서 사라짐이 확인되어야 메인 팀을 제거하며, 서브 파일의 사라짐은 팀 전체 제거가 아니다. 로컬과 WSL 모두 파일 감시기 없이 폴링한다. 주기·지연 조절·누락 판정은 [스케줄러](../src-tauri/src/tail/scheduler.rs)에 둔다.

기존 팀의 세션 파일 읽기·재구성이 실패하면 작업 상태를 보존하고 화면에서는 추정 퇴근으로 표시한다. 정상 파일의 증분 반영은 계속하며, 실패한 경로를 다시 읽거나 삭제가 확인되면 실패 표시를 해제하고 보존한 작업 상태로 복귀한다. 실패를 확인하기 전의 추정이나 단순 파일 수정 시각 변화로 퇴근·재설정을 만들지 않는다. 처음부터 읽지 못한 메인 파일만으로 빈 팀을 만들지 않는다.

## C7. 파싱과 사실의 보존

제품 구분은 레코드와 등록부의 근거를 따른다. 알려지지 않은 필드나 개별 필드의 타입 변경 때문에 해석 가능한 줄 전체를 버리지 않는다. 호출과 결과는 호출 식별자로 연결하고, 내부 통신·계획 작업은 호출과 결과 모두 사용자 업무에서 제외한다. 사용자·다른 에이전트·시스템 문장을 구분해 시스템 응답이 사장 방문으로 보이지 않게 한다. [공통 파서](../src-tauri/src/parse/mod.rs), [Claude](../src-tauri/src/parse/claude.rs), [Codex](../src-tauri/src/parse/codex.rs)

명령 문자열은 정적으로 분류할 뿐 실행하지 않는다. 복합 명령의 전체 성공으로 개별 하위 명령 성공을 단정하지 않는다. 결과의 명시적 종료 상태와 문장 추정을 구분하며, 반려·불명확한 결과를 확정 실패로 세지 않는다. 암호화되었거나 없는 지시 원문은 추측해 채우지 않는다. 복제된 부모 이력은 자식의 새 활동으로 중복 계산하지 않는다.

**미확인:** Claude 동기 서브에이전트의 실제 결과 필드는 [합성 fixture의 출처 설명](../fixtures/README.md) 기준으로 미확인이다. **현재 한계:** Codex 자식 rollout을 별도 팀으로 만들지 않으며 자식 활동을 통합하는 지원을 약속하지 않는다. 지원 형식·명령 매핑표를 이 문서에 복제하지 않고 파서와 fixture를 기준으로 삼는다.

## C8. 상태 전이와 사무실 합성

도구 결과는 대응하는 진행 중 호출이나 백그라운드 작업에만 적용한다. 시작됨은 완료가 아니며 확인된 완료·중지 또는 퇴근 조건까지 작업 상태를 유지한다. 반려·불명확·추정 결과가 확정 오류 수, 무재해 시간, 장애 표시, 확정 성과를 바꾸지 않게 한다. 결재 대기는 직원 상태의 공통 판정으로 유지한다. 시간 전이·장애 누적과 해제·성과 계산은 [classify](../src-tauri/src/office/classify.rs), [stats](../src-tauri/src/office/stats.rs)가 기준이다.

생존 등록부에서 확인했던 세션이 정상 재조회에서 사라지면 침묵 시간을 기다리지 않고 다음 관측 때 확정 퇴근으로 표시한다. 등록부 파싱 불확실은 종료 근거가 아니다. 같은 세션은 생존을 다시 확인하고 종료 이후 새 메인 활동을 읽으면 복귀한다. 등록부로 확인하지 못한 세션은 기존 침묵 추정을 사용하며, `/clear` 전용 감지는 하지 않는다.

서브 작업의 명시적 중단은 완료·퇴근과 구분해 직원 카드에 ‘중단’으로 표시한다. 중단만으로 성공·실패 성과를 만들거나 별도 백그라운드 프로세스 종료를 추정하지 않는다. 같은 직원의 새 활동이나 실행 재개를 확인하면 중단을 해제하며, 단순 메시지 전달만으로 재개를 단정하지 않는다.

직원 카드의 빌드·테스트 테는 해당 직원의 호출과 마지막 확정 결과로 정한다. 진행 중 호출이 있으면 진행 테를 우선하고, 확정 성공은 그 직원의 실패 테를 해제한다. 다른 직원의 결과와 반려·불명확·추정 결과는 이를 바꾸지 않는다. 퇴근 시 테는 숨기되 마지막 확정 결과는 보존한다.

직급·담당·업무와 컨텍스트 크기는 기록으로 확인할 수 있는 만큼만 정하고, 모르는 값을 확정값처럼 표시하지 않는다. **현재 한계:** 다른 세션에서 배운 컨텍스트 크기를 적용하는 규칙은 구현되지 않았다. ‘오늘’ 성과의 날짜 경계 초기화와 이름·방 번호 공간 소진 때의 한계는 [사무실 상태](../src-tauri/src/office/mod.rs)와 [이름 배정](../src-tauri/src/office/names.rs)의 주석을 따른다.

배치·이름은 같은 입력에 안정적이어야 한다. 퇴근 팀은 팀장석·간이석을 점유하지 않으며, 빈자리가 생기면 배치되지 않은 활성 팀에 주되 이미 배치된 팀의 자리는 유지한다. 규모 변경은 사무실·좌석·선택 매핑을 재구성하며 팀의 논리 상태를 초기화하지 않는다. 합동 사무실의 공유 표시도 팀 상태에서 합성한다. [world](../src-tauri/src/office/world.rs)

시간대는 OS 로컬 시계와 [HANDOFF 6.2절 시간표](../design/HANDOFF.md#62-그리기-순서)를 따른다. 캔버스의 창문·조명·램프는 Rust가 정한 같은 단계(`daylight`)를 읽는다. 퇴근·대기 조명이 시간대 조명보다 우선하며, 야근 모드 수동 설정은 크롬에만 적용한다.

오늘 테스트·커밋 누계는 팀별로 보존하고 로컬 날짜가 바뀌면 새 날짜의 값으로 전환한다. 화면을 다시 열거나 같은 결과를 재조회해 누적하지 않는다. 테스트 누계·연속 통과·메달은 대응 호출의 종류와 확정 결과로 계산하며 추정 결과판·도장을 세어 만들지 않는다. 고유 읽기·수정 수는 기존 호출 기록의 고유 경로 수이며 성공한 실제 파일 수로 해석하지 않는다.

## C9. IPC·설정·상세 읽기와 경로 보안

DTO는 [Rust 계약](../src-tauri/src/ipc.rs)에서 생성한 [TypeScript 타입](../src/types/ipc.ts)을 사용한다. 선택 요청 발급 번호와 백엔드가 수락한 번호의 하한은 구분한다. 최신 선택이 실패하면 앞서 발행한 요청의 완료를 기다린 뒤 스냅샷 한 번으로 실제 선택을 복구한다. 그동안 사무실별 최신 상태를 보관하고, 더 늦은 선택이나 더 최신 목록을 과거 실패·복구 응답이 덮지 못하게 한다. 복구도 실패하면 오류를 드러내고 사용자의 같은 사무실 재시도를 허용하며 자동 선택 루프를 만들지 않는다. [선택 처리](../src/store.ts)

설정은 부분 갱신하고 알 수 없는 저장 필드를 보존한다. 기본값은 소리 꺼짐·야근 모드 자동·직원 동물 섞기·OS 알림 켜짐·원문 진단 꺼짐이다. 회사·사장님 이름은 Unicode 문자 수로 제한하고 빈 이름은 기본값으로 처리한다. 저장 실패에도 백엔드 메모리가 바뀔 수 있으므로 다시 읽어 화면을 맞추고 실패를 알린다. [설정](../src-tauri/src/settings.rs), [설정 UI](../src/popup-settings.ts)

같은 앱 데이터 폴더에는 한 프로세스만 쓰도록 기동 때 실행 잠금을 유지한다. 잠금 획득 실패를 포함한 기동 실패는 화면에 알리고 사용자가 원인을 해결한 뒤 재시도할 수 있게 한다. [기동 잠금](../src-tauri/src/lib.rs), [기동 UI](../src/main.ts)

업데이트는 GitHub Releases 의 `latest.json` 과 설치 파일 옆 서명(Tauri minisign)으로만 한다. 사무실이 뜬 뒤 한 번 조용히 확인해 있으면 토스트로 알리고, 설정의 "새 버전 확인"으로도 확인하며, 다운로드·설치는 사용자가 설치 버튼을 누른 뒤에만 한다. 현재보다 높은 버전만 설치하고, 서명이 맞지 않으면 설치를 거부하고 알리며, 다운로드 실패·오프라인은 앱을 멈추지 않는다. 설치 중 설정 팝업을 닫았다 열어도 한 번만 진행한다. Windows 에서는 설치 단계에서 앱이 종료·재시작되고 설정과 사용자 데이터는 남는다. 확인·다운로드는 Rust 플러그인이 하고 세션 내용은 보내지 않는다 (C1). 외부 네트워크 요청은 이 둘뿐이다. [업데이트 UI](../src/popup-settings.ts), [업데이트 상태](../src/update-store.ts)

상세 요약은 메모리에서, 원문 타임라인은 필요한 페이지를 읽는다. 커서는 파일 세대·줄 경계와 결합하며 원본 교체 뒤의 커서를 계속 쓰지 않는다. 한 줄에서 나온 이벤트 묶음을 페이지 경계로 쪼개지 않는다. 창을 닫은 뒤 늦은 응답을 적용하지 않고, 원문 조회 실패가 이미 얻은 요약까지 지우지 않게 한다. 제한·커서 처리·긴 본문 절단은 [상세 읽기](../src-tauri/src/detail.rs)와 [직원 팝업](../src/popup-employee.ts)이 기준이다.

프론트가 보낸 임의 파일 경로를 열지 않는다. 대상 식별자를 현재 사무실·팀·직원과 대조한 뒤 등록된 경로를 결정한다. 경로 이탈, 잘못된 WSL 소속, 허용하지 않은 URL·셸 문자를 거절하고 WSL 접근 조건을 다시 적용한다. 응답 제한 시간은 I/O 취소 보장이 아니다. **현재 한계:** 외부 프로그램으로 폴더를 여는 순간까지 경로 교체를 완전히 막는 보장은 없다. [경로 검증과 열기](../src-tauri/src/detail.rs)

## C10. 상태와 연출의 경계

전체 상태가 진실이고 cue는 일회성 연출 힌트다. 직원의 DOM·액터 키에는 팀과 직원을 함께 사용한다. 같은 상태를 다시 받았다고 사건을 다시 재생하지 않는다. 숨김·사무실 전환·재구성 시 이전 큐와 진행 중 연출의 세대를 끊고, 복귀 때 과거 사건을 밀린 재생처럼 보여 주지 않는다. 새 상태의 배치는 즉시 적용한다. 모션 축소·첫 표시·숨김 복귀의 시각 처리 기준은 [HANDOFF](../design/HANDOFF.md), 구현은 [renderer](../src/office/renderer.ts)와 [anim-queue](../src/office/anim-queue.ts)에 둔다.

계획 진행·연속 통과·메달 유효 상태·날짜별 누계·고유 경로 수는 같은 논리 종료 시각과 로컬 시간 조건에서 전체 재구성과 증분 적용의 값이 같아야 한다. 메달을 화면 표시 시각부터 다시 시작하거나 cue를 재생해 복원하지 않는다. 감정 표식·자료실·경비실 방문·하이파이브 같은 지난 사건 연출은 이 보존 상태에 포함하지 않으며 전환·창 복귀·재구성 뒤 재생하지 않는다.

소리는 기본 꺼짐이고 사용자가 켠 뒤의 제스처로 오디오를 준비한다. 준비되지 않은 순간의 사건음을 쌓지 않으며 음소거 전 큐가 나중에 울리지 않게 한다. 숨김·전환·재구성 시 즉시 중단한다. 복귀 후 현재 타이핑 자세는 소리를 다시 낼 수 있지만 직원 수만큼 중첩하지 않는다. 인터폰·경보·무재해 리셋은 실제 사건 연결점에서만 울린다. 재개 실패를 무한 재시도하지 않는다. [sound](../src/office/sound.ts), [actors](../src/office/actors.ts)

경로·세션 문장 등 외부 문자열을 HTML로 해석하지 않는다. 경과 시간 치환도 인용된 코드 내용을 바꾸지 않는다. [문자열 처리](../src/text.ts), [팝업](../src/popup-employee.ts)

## C11. 로컬 진단과 비밀 제거

운영 로그와 알 수 없는 레코드 진단은 로컬에 크기·보존 상한을 두고, 진단 실패로 수집 루프를 멈추지 않게 한다. 기본 진단은 구조·집계 정보이며 지시·명령·결과 원문을 넣지 않는다. 원문 진단은 명시적으로 켠 동안만 제한된 발췌를 허용하고 화면에서 설명과 켜짐을 알린다. 끄면 원문 수집을 중단하고 이전 발췌도 메모리와 진단 파일에서 제거한다. 디스크 원문 제거가 실패하면 수집 중단과 제거 성공을 구분해 실패를 알리고, 접근 문제를 해결한 뒤 수집을 다시 켜지 않고 제거를 재시도할 수 있게 한다. 제거 성공 전에는 디스크 원문이 지워졌다고 알리지 않는다. 보존·길이·집계 상한은 [diag](../src-tauri/src/diag.rs), [운영 로그](../src-tauri/src/oplog.rs)가 기준이다.

복사할 진단은 원본 세션 내용 대신 상태·오류·탐색 후보 정보를 사용한다. 홈·루트·프로젝트·배포판 등 식별 가능한 값은 진단 복사 경로에서 치환하거나 해시 처리한다. 이 처리를 모든 운영 로그나 사용자가 보는 경로가 이미 익명이라는 뜻으로 확대하지 않는다. 복사 실패와 원문 설정 저장 실패는 사용자에게 알린다. [진단 생성](../src-tauri/src/diag.rs), [설정 UI](../src/popup-settings.ts)

## C12. 검증 불변식과 fixture

같은 논리 종료 시각에서 전체 재구성·증분 적용·허용된 병합 순서는 같은 최종 상태를 만들어야 한다. 파일 재설정과 재조회는 성과·직원·사건을 중복 누적하지 않아야 한다. 파서의 모르는 입력·혼합 명령·반려·시간 역행, 선택·상세의 늦은 응답, WSL 접근 차단과 경로 이탈은 동작 회귀로 검증한다. [스케줄러 검증](../src-tauri/src/tail/scheduler.rs), [상세 검증](../src-tauri/src/detail/tests.rs), [선택 검증](../src/store.test.ts), [연출 검증](../src/office/renderer.test.ts). 코드와 검증이 가리키는 `S` 번호의 뜻은 [시나리오 번호표](SCENARIOS.md)

원본 세션은 저장소 밖에 두고 읽기만 한다. fixture에 넣는 레코드는 허용 목록을 바탕으로 식별 정보·비밀을 제거하고, 필요한 형식·연결 관계·시간 간격만 남긴다. 자동 익명화가 사람 이름과 모든 비밀을 찾아낸다고 가정하지 않으며 최종 사람이 확인한다. 실제 발췌와 합성을 구분하고 미확인 형식을 실제로 확인한 자료처럼 쓰지 않는다. [익명화 도구](../tools/anonymize.py), [fixture 출처](../fixtures/README.md)

실제 자료를 사용하는 선택적 검증은 명시된 외부 경로에서만 수행하고 원문을 결과에 내보내지 않는다. 테스트 명령은 [BUILD](BUILD.md), 화면·접근성·실제 환경의 수동 검수는 [HANDOFF](../design/HANDOFF.md)에 둔다. 개별 구현 호출이나 정적 값 복제를 검증 목표로 삼지 않는다.

## C13. 성능 목표와 지연 대응

다음 값은 **목표**이며 보장이나 개인 PC 측정 결과가 아니다. 조건은 활성 팀 4개 중 WSL 1개, 직원 12명, 세션 5MB와 서브 파일 2MB 네 개이며 60초 동안 평균과 p99를 관찰한다. 폴링 주기는 종단 지연 보장이 아니다.

| 항목 | 목표 |
|---|---|
| Hot stat | 로컬 1ms 미만, UNC p99 20ms 미만 |
| Hot 읽기 포함 100KB | 30ms 미만 |
| 직렬화·emit / 프론트 상태·카드 적용 | 각각 2ms / 5ms 미만 |
| 파일 변경부터 화면 반영 | Hot 500ms 미만 |
| 새 파일부터 목록 표시 | 로컬 3.5초 미만, WSL 35초 미만 |
| 로컬 프로젝트 폴더 25개 Scan | 10ms 미만 |
| 유휴 CPU / WebView2 포함 메모리 | 각각 2% / 150MB 미만 |

지연이 연속된 호스트만 폴링을 늦추고 회복도 그 호스트 단위로 판단한다. 다른 호스트를 함께 늦추지 않으며 WSL 통신 지연은 화면에 알린다. 임계값은 [스케줄러](../src-tauri/src/tail/scheduler.rs)가 기준이다. **현재 한계:** [probe](../src-tauri/src/bin/probe.rs)의 부분 벤치마크만으로 위 전체 조건이나 실제 배포판 종료 중 비기동을 검증했다고 할 수 없다. 측정 방법은 [BUILD](BUILD.md)에 둔다.
