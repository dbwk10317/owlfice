# 규칙

같은 실수가 두 번 이상 난 것만 적는다 (AGENTS 7절). 상황 → 규칙 → 이유.

## CSS 초기화는 특이성 0 으로

- 상황: `tokens.css` 의 `.ow-app button { padding: 0; margin: 0 }` 이 `<button>` 으로 만든 카드·행·그룹·`.ow-btn` 의 padding·margin 을 이겼다. 티커 항목에서 한 번(선택자를 한 단계 더 써서 우회), 현황판·사이드바 전체에서 또 한 번(T52).
- 규칙: 요소 선택자로 쓰는 초기화는 `:where(...)` 로 감싸 특이성 0 으로 둔다. 컴포넌트 쪽에서 선택자를 더 붙여 우회하지 않는다.
- 이유: 컴포넌트는 `<button>` 인지 `<div>` 인지가 바뀌어도 같은 클래스 규칙으로 보여야 한다. 우회 선택자는 다음 컴포넌트에서 같은 버그를 다시 낸다.

## 개발 화면도 완전한 DTO로 검사

- 상황: 소품 비교 페이지의 직원 목록과 직원 연출 페이지의 공용 소품 값이 빠졌는데 강제 캐스팅과 타입 검사 제외로 숨겨져 실행 중 오류가 났다.
- 규칙: 개발 화면의 DTO는 `src/test-office.ts` 생성기를 쓰고 `dev/`도 타입 검사에 포함한다. 불완전한 객체를 DTO로 강제 캐스팅하지 않는다.
- 이유: 데이터 계약이 바뀌면 앱과 검증 화면이 함께 실패해야 깨진 비교 도구를 통과 근거로 쓰지 않는다.

## PowerShell의 파일 검색 범위

- 상황: `rg dev/*.ts`처럼 셸이 펼치지 않는 경로 패턴을 넘겨 검색이 두 번 실패했다.
- 규칙: 파일 목록은 `rg --files`, 확장자 범위는 `rg -g '*.ts' <패턴> dev`로 지정한다.
- 이유: PowerShell에서도 존재하는 경로와 rg의 필터를 분리해 같은 검색이 동작하게 한다.
