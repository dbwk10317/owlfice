# 코드 설계 규칙

새 기능·버그 수정·리팩터링에 적용하는 필수 설계 규칙이다. 논문·저서·공식 문서의 원칙을 Owlfice에 맞게 종합했다. 기존 코드 전체를 일괄 수정하라는 뜻은 아니다. 작업 순서는 [AGENTS.md](../AGENTS.md), 동작은 [CONTRACTS.md](CONTRACTS.md), 검증 명령은 [BUILD.md](BUILD.md)를 따른다.

규칙은 수정 범위에서 지키고, 조건이 붙은 규칙은 그 조건이 있을 때 적용한다. 기존 계약·호환성과 충돌하면 기능을 몰래 바꾸지 말고 충돌 이유와 수정 범위를 먼저 정한다. 서식·명명 관례는 저장소의 포맷터·린터 설정을 따른다.

## 공통

- **변경 이유로 나눈다.** 모듈은 함께 바뀌는 규칙과 감춰야 할 구현 결정을 묶는다. 줄 수나 실행 순서만으로 파일을 자르지 않는다.
- **호출자가 알아야 할 것을 줄인다.** 공개 진입점은 의미 있는 작업을 완결하고 구현 순서·저장 방식은 안으로 숨긴다. 파일을 나눈 뒤에도 호출자가 내부 순서를 조립해야 한다면 경계를 다시 잡는다.
- **상태의 주인을 하나로 둔다.** 같은 사실을 여러 곳에서 독립적으로 갱신하지 않는다. 파생 값은 계산하고, 캐시가 필요하면 원본과 무효화 책임을 명시한다.
- **의존 방향을 지킨다.** 계산·변환 코드는 이를 사용하는 CLI·화면·파일 처리 코드를 참조하지 않는다. 순환 import와 모든 것을 모으는 공용 모듈을 만들지 않는다.
- **경계에서 검증한다.** 외부 입력은 파싱·검증 뒤 내부 타입으로 넘긴다. 오류와 알 수 없는 결과를 성공이나 빈 값으로 바꾸지 않는다.
- **역할을 중복하지 않는다.** Rust가 세션의 업무 상태를 판정하고, TypeScript는 DTO를 표시한다. 프론트가 방·자세로 업무 상태를 다시 추론하지 않는다. Python은 개발·검증 도구를 맡는다.

## Rust

- 서로 배타적인 상태는 `enum`으로 표현한다. 함께 성립할 수 있는 독립적인 속성까지 하나의 거대한 상태 열거형으로 합치지 않는다.
- 같은 기본 타입이라도 혼동하면 오류가 나는 식별자·단위는 필요한 경계에서 `newtype`으로 구분한다. 의미가 불분명한 여러 `bool` 인자는 이름 있는 타입으로 표현한다.
- 상태 변경과 자원 해제의 책임을 소유자에 모은다. 파일을 나누기 위해 상태를 복제하거나 `Arc<Mutex<_>>`로 공유하지 않는다.
- 모듈 내부는 비공개로 두고 필요한 항목만 `pub(super)`·`pub(crate)`로 연다. 분리를 쉽게 하려고 필드를 일괄 공개하지 않는다.
- 입력·시간·I/O를 다루는 경계와 판정 규칙을 구분한다. 규칙에 필요한 값만 넘기고, 테스트를 위해 전역 상태를 추가하지 않는다.
- `trait`은 실제로 필요한 공통 동작이나 교체 경계에 쓴다. 클래스 계층을 흉내 내거나 구현체 하나를 감싸기 위해 만들지 않는다.
- 복구 가능한 실패는 `Result`로 전달하고 호출 경계에서 맥락을 붙인다. 외부 입력·I/O 경로에서 `unwrap`·`expect`로 종료하지 않는다.

## TypeScript

- 상태별로 필요한 데이터가 다르면 판별 필드가 있는 유니온으로 묶고, 분기는 빠짐없이 처리한다. 선택 속성 여러 개로 불가능한 조합을 허용하지 않는다.
- 외부 값은 `unknown`에서 검사한다. `any`·강제 캐스팅·non-null assertion으로 검증이나 낡은 타입 문제를 덮지 않는다. IPC 타입은 생성된 정의를 사용한다.
- 타입 추론과 좁히기를 우선하고, 제네릭은 입력·출력 사이에 실제 타입 관계가 있을 때 쓴다. 변경을 통과시키려고 엄격한 타입 검사 설정을 약화하지 않는다.
- 배치·선택·문자열 계산은 DOM·Pixi 객체의 생성과 수명 관리에서 분리한다. 계산 모듈은 렌더러를 import하지 않는다.
- DOM·Pixi 객체, 리스너, 타이머, 구독은 생성한 소유자가 해제한다. 화면 재생성·제거 때 중복 등록이나 남은 참조가 없어야 한다.
- 클래스는 함께 유지되는 상태·자원의 수명을 관리할 때 쓴다. 독립적인 계산은 함수와 모듈로 둔다. 모든 함수에 인터페이스나 서비스 클래스를 붙이지 않는다.

## Python

- 변환 로직은 입력을 받아 결과를 내고, CLI가 인자·파일·환경·출력을 처리한다. 변환 모듈을 import하는 것만으로 파일 접근이나 실행을 시작하지 않는다.
- 단순 작업은 함수로 둔다. 여러 연산이 같은 상태와 불변식을 공유할 때 클래스를 쓰고, 값의 묶음이 필요할 때 `dataclass`를 검토한다.
- 외부 JSON·CLI 입력의 형태와 범위를 검사한다. 구조를 추측한 채 딕셔너리를 계속 전달하거나, 오류를 빈 레코드로 대체하지 않는다.
- 실패는 필요한 맥락을 보존해 전달하고 CLI 경계에서 종료 코드와 메시지로 바꾼다. 광범위한 예외 처리로 계속 진행하지 않는다.
- 필요한 이름을 명시적으로 import한다. 경로 조작이나 재수출 계층으로 잘못된 모듈 의존을 숨기지 않는다.
- 공개 함수의 입력·출력 형태는 타입 힌트로 드러내고 내부 구현은 비공개 이름으로 구분한다. 타입 힌트는 런타임 입력 검증을 대신하지 않는다.

## 분리와 추상화의 판단

| 관찰한 문제 | 적용할 판단 |
| --- | --- |
| 서로 다른 기능 변경이 같은 파일·공유 상태를 계속 건드린다 | 변경 이유와 상태 소유자를 기준으로 경계를 나눈다. |
| 계산을 확인하려는데 창·파일·네트워크부터 준비해야 한다 | 경계가 입력을 읽고, 계산에는 필요한 값만 전달하게 한다. |
| 분리 뒤 호출 순서·공개 필드·전달 함수만 늘었다 | 인터페이스가 숨기는 복잡성이 있는지 확인하고, 이득이 없으면 합친다. |
| 비슷한 코드가 보인다 | 모양보다 같은 규칙인지 확인한다. 함께 바뀌는 규칙만 공유하고 우연히 비슷한 코드는 억지로 묶지 않는다. |

클래스·trait·제네릭·계층 수와 파일 줄 수는 완료 기준이 아니다. 기존 모듈로 해결할 수 있는지 먼저 보고, 새 추상화는 감출 결정이나 실제 교체 지점이 있을 때만 만든다.

## 리팩터링 완료 기준

- 바뀌는 책임과 외부에 남길 진입점을 먼저 정한다. 이동만을 위한 전달 함수·설정·추상 계층은 추가하지 않는다.
- 기존 입력에 대한 출력·상태 전이·오류 전달을 유지한다. 동작 변경이 필요하면 별도 수정으로 다루고 계약을 확인한다.
- 기존 회귀 검증을 통과시키고, 새 경계에서 놓칠 수 있는 동작만 추가 검증한다. 파일 이동 때문에 기대값을 바꾸지 않는다.
- 검토할 때는 **변경 이유가 분리됐는가 / 상태 소유자가 하나인가 / 의존이 한 방향인가 / 호출자가 알아야 할 세부사항이 줄었는가 / 실패 의미가 보존되는가**를 확인한다. 하나도 개선되지 않았다면 파일 이동 자체를 성과로 삼지 않는다.
