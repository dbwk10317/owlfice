# Owlfice 디자인 인계서

> 대상: 프론트 구현 담당 (Tauri 2 + Vite + TypeScript + PixiJS 8). 동작 규칙은 [CONTRACTS](../docs/CONTRACTS.md)를 따른다. 이 문서는 "어떻게 보이고 어떻게 그리는가"를 정한다.
> 시각 참조는 캔버스 시안 [Owlfice 디자인 0.2.0](https://claude.ai/artifact/4PtdXQYh8xL3BQwJBCkgfV)이다. 원본 파일은 `design/project/*.dc.html` (0.1.0 시안은 git 태그 v0.1.1 에만 남긴다. 이 폴더에 두 버전을 섞지 않는다).

## 0. 무엇을 어디에 쓰나

값이 서로 다르면 위에 있는 것이 이긴다.

그림은 손으로 고치지 않는다. `design/tools/owlfice_art.py` 를 고치고 다시 만든다.

```bash
python design/tools/owlfice_art.py
```

실행하면 시트, 평면도, 미리보기, 참조 렌더를 모두 다시 만들고 끝에 겹침·누락 검사를 돈다. 검사가 실패하면 예외로 멈춘다.

## 1. 원칙

- **픽셀아트는 가운데 사무실 캔버스 안에서만 쓴다.** 사이드바, 현황판, 팝업, 로딩 화면의 글과 컨트롤은 흰 바탕의 차분한 웹 UI다.
- **익살은 문구와 사무실 연출이 맡는다.** UI 크롬은 장난스럽게 만들지 않는다. 이모지는 쓰지 않는다.
- **추정은 늘 구분해서 보인다.** 점선 테두리 + "~인 듯" 문장 + `추정` 꼬리표 중 그 자리에 맞는 것을 쓴다 ([CONTRACTS C2](../docs/CONTRACTS.md#c2)).
- **오프라인 앱이다.** 글꼴은 앱에 묶는다. 외부 CDN을 쓰지 않는다.
- **색은 토큰으로만 쓴다.** 야근 모드(4.8절)는 `tokens.css` 의 `[data-theme="night"]` 블록이 변수 값만 바꿔서 된다. 컴포넌트 CSS 에 `#fff` 같은 직접 색을 넣지 않는다.
- **글자가 상자에 붙지 않는다.** 칩 안쪽 8 이상, 행 안쪽 12/18, 카드 안쪽 14/16. `--ow-ink-3` 보다 흐린 글자는 어디에도 없다 (타임라인 시각, 티커 시각 포함).

## 2. 레이아웃

### 2.1 기본형 (너비 1100 이상, 높이 640 이상)

```
| 사이드바 240 | 가운데: 머리말 56 + 무대 (나머지) | 현황판 320 (머리 56 · 목록 · 티커 40) |
```

- 사이드바: 간판 60, 지표 띠 68 (아래 여백 10), 토스트 32 (있을 때, 아래 여백 10), 목록 (세로 스크롤), 바닥 44.
- 가운데: 머리말 56 아래 무대. 캔버스는 무대 한가운데, 남는 곳은 무대 바탕 (`--ow-stage` + 16px 점 격자 + 가장자리 비네트 `ow-stage::before`). 캔버스 아래 바닥 그림자 `ow-stage__floor` (타원, blur 14, 너비 min(760, 90%)). 무대 오른쪽 아래 `ow-stage__tools`: `center`(사무실 가운데로)·`fullscreen` 버튼, 흰 바탕 + 테두리.
- 현황판: 머리 56, 카드 목록 (안쪽 여백 12, 카드 사이 10, 세로 스크롤), 티커 40.

### 2.2 창 크기 구간

배율은 3.1절 공식이 정한다. 아래 배율은 DPR 100% 기준이다.

| 창 너비 | 사이드바 | 캔버스 | 현황판 | 시안 |
|---|---|---|---|---|
| 1600 이상 (높이 720 이상) | 240 | 2× (들어가면 3×) | 320 | 메인 · 대기업 |
| 1100–1599 | 240 | 1× | 320 | 메인 · 중소기업 |
| 900–1099 | 240 | 1× | 접힘. 머리말 오른쪽 끝 `panel` 아이콘 버튼. 누르면 무대 위로 320 드로어 | 960 드로어 |
| 720–899 | 레일 48 | 1×. 머리말 대신 52 높이 띠에 사무실 이름과 "오늘의 업무" 칩 | 접힘 | 800 레일 |
| 720 미만 | 숨김. 48 높이 띠의 `<select>` 로 사무실 선택 | 1× 고정, 끌어서 이동, 오른쪽 아래 미니맵 | 접힘 | 480 최소 이하 |

| 창 높이 | 동작 |
|---|---|
| 640 이상 | 전부 표시 |
| 480–639 | 티커 숨김. 카드는 압축형. 로딩 단계 목록은 3줄만 |
| 480 미만 | 캔버스 세로로도 끌어서 이동 |

- 리사이즈는 `ResizeObserver` 100ms 디바운스. 재배치는 애니메이션 없이 즉시. 사이드바 접기·펼치기와 드로어만 200ms.
- 레일 항목에 마우스를 올리거나 누르면 240 사이드바가 레일 위로 겹쳐 열린다 (`--ow-z-rail-pop`, 그림자 `--ow-shadow-drawer` 좌우 반전). 레일 항목 `ow-rail__item` 은 동 색 바탕 32px 타일에 동 글자 11/700, 오른쪽 아래 10px 상태 점, 선택은 검은 2px 테(바깥 2px 띄움). 퇴근은 상태 점만 50% 불투명으로 하고 글자 대비는 유지한다. 허가 대기는 타일 전체를 `--ow-ask` 로.
- 팝업은 최대 90vw × 90vh, 안쪽 스크롤. 너비 720 미만이면 전체 화면 시트.

### 4.2 상태 점 `ow-dot`

14×14 상자 안의 8px 점. 범례는 하나로 통일한다 ([CONTRACTS C3](../docs/CONTRACTS.md#c3)).

| `data-state` | 점 | 뜻 |
|---|---|---|
| `working` | 초록 | 근무 중 |
| `waiting` | 초록, 1.1초 깜빡임 (`steps(2,start)`) | 결재 대기 또는 응답 대기 |
| `sleepy` | 노랑 | 졸음 |
| `idle-alive` | 노랑 + 줄에 "대기 중" 칩 | 30분 조용하지만 프로세스 살아 있음 |
| `incident` | 빨강 | `[340,267]` |
| `off` | 회색 | 퇴근 |

| `data-ring` | 테 | 뜻 |
|---|---|---|
| `run` | 노란 2px 테 | 빌드·테스트 진행 중 |
| `fail` | 빨간 2px 테 | 마지막 빌드·테스트 실패 |
| `lag` | 1.5px 회색 점선 테 | 통신 지연 (WSL) |

허가 대기는 점 아래(행) 또는 옆(범례)에 `approval` 아이콘 14px `--ow-ask`. 레일에서는 상태 점 자리를 `--ow-ask` 로 칠한다.

고유 경로 수는 **성공적으로 처리한 실제 파일 수가 아니라 기록된 호출의 고유 경로 수**다. 실패·반려 호출도 포함하며, 별도의 파일 시스템 탐색을 하지 않는다. **현재 한계:** Codex 여러 파일 패치는 첫 경로만 보존한다. 검색·git 조회까지 포함하는 `counters.read`나 호출 횟수인 `counters.edit`로 대신 세지 않는다.

새 테스트 누계·메달은 대응 호출의 확정 결과만 사용한다. Mixed·추정·반려·결과 미확인은 합격/실패 누계에서 제외한다. `&&` 묶음 실패는 테스트 실행 전에 실패했을 수 있으므로 테스트 실패 숫자가 확인될 때만 실패로 센다. 테스트 완료의 실패·반려·불명확 결과는 연속 통과를 끊고, 다른 업무나 아직 완료하지 않은 백그라운드 시작은 끊지 않는다. 이미 획득한 메달은 연속이 끊겨도 원래 만료 시각까지 유지한다.

### 5.3 자리·자세와 일회성 연출의 우선순위

퇴근·개별 종료는 해당 직원의 활동과 방문 연출을 가린다. 근무 중에는 **허가 대기(출입문) → 진행 중 도구 → 반려 직후 유지 → 사용자 응답 대기 → 장애 상황실(부장) → 계획 진행(회의실) → 그 밖의 작업·침묵 자세** 순으로 판정한다. 기존 반려 유지와 응답 대기 전이의 길이는 코드가 기준이며, 새 방문을 붙이려고 늘리지 않는다. 팀 졸음 전이는 기존처럼 응답 대기를 끝낸다.

출고장·외근·거래처 미팅은 실제 도구 활동이므로 장식 동작으로 덮지 않는다. 장애 소품·카드 표시는 자리와 독립이다. 허가를 기다리는 부장은 출입문에 있고, 팀원은 자기 활동을 유지해도 장애 표시는 남는다. 계획 중 `ExitPlanMode` 질문이 오면 `planning`은 유지하되 허가 대기 자리가 우선한다.

자료실·경비실 방문은 본래 업무 상태를 바꾸지 않는 일회성 연출이다. 더 높은 활동이 있으면 생략하고, 도중에 생기면 즉시 끊어 현재 상태의 자리로 간다. 반려 사건의 경비실 방문은 같은 반려 유지 안에서 처리하며 4초 뒤 다시 예약하지 않는다. 졸음·휴식은 이 방문보다 낮다. 장애가 있는 팀에서는 새 장식 자세(stretch·drink·phone·highfive)를 시작하지 않는다. 허가 대기·퇴근도 새 장식 자세를 막는다.

장애·퇴근은 **회의실 연출만 중단하며 `planning`을 지우지 않는다**. 복귀하면 현재 활동과 위 우선순위로 자리를 다시 정한다. 사무실 전환·창 복귀·재구성은 지난 감정 표식·방문·자세 사건을 재생하지 않는다. 10절의 움직임 줄이기도 같은 경계를 따른다.

### 5.4 새 방의 진입·유지·종료·중단

회의실은 계획 업무용이며 기존 MCP·스킬의 거래처 미팅실과 구분한다. 자료실은 컨텍스트 압축용이며 기존 파일 열람의 소스 서고와 구분한다. 새 방의 격자·수용 인원은 6.5절 평면도 규약을 따른다.

| 방 | 진입 | 유지 | 종료 | 중단·복귀 |
|---|---|---|---|---|
| 회의실 | `EnterPlanMode` 호출을 관측해 `planning` 설정 | 대응 `ExitPlanMode`의 답을 기다리는 동안에도 논리 상태 유지. 실제 자리는 5.3절 | 해당 종료 호출의 확정 성공·반려 결과에 연결해 계획 종료. 일반 질문의 답·승인 문구는 쓰지 않음 | 장애·퇴근은 연출만 중단. 복귀 시 계획 상태와 현재 활동으로 자리 결정 |
| 자료실 | 직원의 새 `ContextCompaction` 사건 | 허용된 경우 새 cue 수신부터 이동을 포함해 4초 방문, 파쇄기 연출. 카드에는 행적 한 줄 | 원래 자리가 아니라 **현재 상태가 정하는 자리**로 복귀 | 더 높은 활동·전환·숨김·재구성에서 중단하고 밀린 방문을 재생하지 않음 |

## 6. 사무실 캔버스 구현 규약

### 6.1 좌표와 배율

- 1× 캔버스 520×320. 격자 24×16, 타일 24×12 (2:1 다이아몬드). 벽 높이 48.
- 격자 → 화면: `x = 212 + (gx − gy) × 12`, `y = 60 + (gx + gy) × 6 − z` (1× 픽셀).
- 배율은 **장치 픽셀** 기준 정수다 (2.2절):

```ts
const dpr = window.devicePixelRatio;
const scale = Math.max(1, Math.floor(Math.min(availW * dpr / 520, availH * dpr / 320)));
// 백킹 크기 = (520·scale, 320·scale) 장치 픽셀. CSS 크기 = 백킹 / dpr (소수여도 된다)
app.renderer.resize(520 * scale, 320 * scale);            // resolution: 1, antialias: false, roundPixels: true
app.stage.scale.set(scale);
canvas.style.width = `${520 * scale / dpr}px`;
canvas.style.height = `${320 * scale / dpr}px`;
TextureStyle.defaultOptions.scaleMode = 'nearest';
```

- DOM 오버레이 좌표 = 1× 좌표 × scale / dpr (CSS px). 머리말 배율 칩은 `scale` 을 보인다.
- 720 미만 패닝: 캔버스 1× 고정, 무대보다 크면 끌어서 이동. 미니맵은 같은 렌더를 120×74 로 줄인 것 + 보이는 영역 사각형.

### 6.2 그리기 순서

`design/tools/owlfice_art.py` 의 `render_scene` 이 정답이다. Pixi 컨테이너를 이 순서로 만든다.

1. `shell/<테마>` 를 격자 (0,0)에.
2. 바닥 타일 24×16장. 규칙은 `floorplan.floorRule`.
3. `layer: decal` 과 `layer: wall` 배치. 그 위에 코드가 그리는 벽 요소: 칸반 포스트잇, 근태판 자석, TV 그래프 선.
4. `layer: window` (창문). **조명 색을 곱하지 않는 컨테이너.**
5. 월드: `layer: world`·`fx` 배치 + 직원 + 휴지통 종이 + 피자 상자를 `depth` 오름차순으로. 같으면 배치 배열 순서 → 직원 순서. Pixi `sortableChildren`, `zIndex` 는 (depth, 순번) 순서를 지키는 정수 (`src/office/floorplan.ts` 의 `zIndexOf`).
6. `layer: overlay` (장애 빛).
7. 조명 색 곱하기 (`floorplan.lightTints`, 아래 시간표·대기 `#B4B4BE`·퇴근 `#6E6E82`): 1·2·3·5 컨테이너에 `tint`. 창문(4)과 빛(6)은 제외. 바뀔 때 1.5초 보간.
8. DOM 오버레이 (4.4절).

`depth` 는 배치마다 `floorplan.json` 에 적혀 있다. 움직이는 직원은 `gx + gy`, 좌석에 앉으면 좌석의 `depth`.

시간표는 OS 로컬 시각 기준이다. Rust가 `TeamDto.daylight: "day" | "evening" | "night"`를 정하고 창문·조명·램프가 같은 값을 읽는다. 창문 스프라이트의 `dusk`는 `evening`에 대응한다. 프론트가 별도로 시각을 판정해 캔버스 안의 낮·밤이 어긋나게 하지 않는다.

| 시각 | 창밖 | 조명 곱하기 | 책상 램프 | 야근 모드가 자동인 크롬 |
|---|---|---|---|---|
| 06–17 | day | 없음(흰색) | 꺼짐 | 주간 |
| 17–20 | dusk | `evening #F6E6C4` | 꺼짐 | 주간 |
| 20–06 | night | `night #F2DEAD` + 램프 비네트 | 켜짐 | 야근 |

모두 퇴근이면 `off`, 남은 팀이 모두 S58 대기 중이면 `dim`, 그 밖에는 시간표 조명이다. 순서는 **off > dim > night/evening/day**다. 창밖 단계는 조명 덮어쓰기와 독립이며 책상 램프는 실제 조명이 `night`일 때만 켠다. 수동 야근 토글은 크롬만 바꾸며 창문·조명·램프를 바꾸지 않는다. 06·17·20·22시 앞뒤 1분과 절전 복귀의 시각 건너뛰기를 검사하고, 복귀 후 첫 틱에 현재 단계가 되어야 한다.

### 6.3 스프라이트 시트 규약

올빼미는 24px 타일에 맞춰 약 14×18로 그린다. 프레임 규격은 6.4절을 따른다. 색은 한 테마에 20색 안팎, 세 테마를 합쳐 약 60색이다. 생성기 부품 시트를 1차 어셋으로 사용하며 손그림 교체는 미정이다.

- 형식은 PixiJS `Spritesheet` JSON (TexturePacker hash). `Assets.load('owls.json')` 로 바로 읽힌다.
- 모든 프레임에 `anchor`(비율)와 `anchorPx`(정수 픽셀)가 있다. **소수 오차를 피하려면 `anchorPx` 를 쓴다**: `sprite.anchor.set(ax / w, ay / h)` 대신 `sprite.pivot.set(ax, ay)`.
- 기준점의 뜻: 그 텍스처 픽셀의 왼쪽 위 모서리가 배치 좌표 `(x, y)` 에 온다. 소품은 발자국 (0,0) 꼭짓점, 올빼미는 발.
- 이름 규칙: `office.json` 은 `<소품>/<상태>`, 상태가 하나면 `/default`. 소품별 메타(발자국, 높이, 상태 목록, fps, 슬롯, 설명)는 `office.json → owlfice.props`.
- 프레임은 잘라내기(trim) 없이 저장했다. `trimmed: false`.

### 6.4 올빼미

- 프레임 16×24, 발 기준점 `(8, 23)`. 레이어를 같은 위치에 겹친다: `body/<종>/…` → `outfit/<옷>/…` → `wear/<단계>/…` → `role/<담당>/…`. 담당 프레임이 없는 자세(예: 날개를 든 자세의 색상표)는 건너뛴다. 수습은 담당 레이어가 없다.
- 프레임 이름: `<레이어>/<변형>/<자세>_<방향>_<번호>`, 애니메이션 이름: 번호를 뺀 것 (`body/eagle/walk_f`).
- 종: 수리부엉이 `eagle`, 칡부엉이 `longeared`, 금눈쇠올빼미 `little`, 가면올빼미 `barn`, 소쩍새 `scops`. 직원 종 = `employeeSpecies[hash(agent_id) % 5]` (이름과 같은 해시). 흰올빼미 `snowy` 는 사장님 전용.
- 옷: `bujang|gwajang|daeri|sawon` × `claude|codex|gemini`, 사장님 `boss`(보라 정장, 금 넥타이, 왕관), 사서 `librarian`(초록 카디건). 직급 구분: 부장 넥타이·안경, 과장 조끼, 대리 소매 걷음, 사원 사원증.
- 근속: 직원별 `hiredAt` 뒤 1시간은 전원 소매 걷음·부장 넥타이 느슨, 3시간은 눈 밑 1px 그림자 추가, 6시간은 어깨 수건 추가. `outfit/<옷>-worn/…`은 지워야 하는 소매·넥타이를 복구하고 `wear/1|2|3/…`을 누적해 얹는다. 사장님·사서와 카드 아바타에는 적용하지 않는다. 미리보기 `sprites/preview/wear.png`.
- 담당: `backend` 검은 터틀넥 깃, `frontend` 색상표, `qa` 돋보기, `devops` 공구벨트, `writer` 귀에 꽂은 펜.
- 5종 × 4직급 = 20가지 기본형에 담당 6가지와 제조사 3색이 겹쳐 수백 가지가 나온다. 미리보기는 `sprites/preview/owls-20.png`.

- 손에 드는 물건: `office.json` 의 `held_*` 를 `owls.json → owlfice.anchors[<자세>_<방향>_<번호>].hand` 에. 말풍선·배지는 `head` 기준점.

### 6.7 참조 렌더로 검수하기

`design/assets/office-claude-day.png`, `office-claude-evening.png`, `office-codex-night-smb.png`, `office-codex-day.png`, `office-gemini-day.png` 는 `make_canvas_images()` 의 고정 상태(직원 배치, 소품 상태, 칸반, 자석, 전광판)로 그린 그림이다. 앱 렌더러에 같은 상태를 넣고 1× 로 `renderer.extract` 한 결과가 **픽셀 단위로 같아야** 한다. 반투명 픽셀(장애 빛, 김, 램프 비네트)은 채널당 ±2 를 허용한다. 조명(저녁·야간·소등)을 곱한 장면은 GPU 가 반올림하고 참조가 내림이라 불투명 픽셀도 채널당 ±1 을 허용한다. 이 비교를 T18·T23 완료 기준에 넣기를 권한다.

## 9. 빈·로딩·오류 상태

[CONTRACTS C3](../docs/CONTRACTS.md#c3)의 빈 상태·실패 처리를 따른다. 화면은 4.7절. 추가로:

- 세션 파일 파싱 실패: 사이드바 행 경고 아이콘, 가운데는 빈 사무실(직원 없음), 현황판 "출근한 직원이 없습니다".
- 선택한 사무실이 퇴근: 조명 off 1.5초 보간 + 캔버스 위 DOM 팻말 "퇴근했습니다" (흰 알약, 13/600, 캔버스 가운데). 다른 사무실을 고르라는 안내는 사이드바 선택 띠가 없는 것으로 충분하다.
- 설정 파일 손상: 로딩 1단계 줄을 경고 모양으로 "창립 서류가 찢어졌습니다. 새로 작성합니다." 그 뒤 규모 선택부터.

## 10. 접근성

- **초점 순서**: 간판 → 사이드바 행(로빙 tabindex, ↑↓ 로 이동, Enter 선택, → 상세) → 머리말 버튼 → 현황판 카드(카드는 `<article>`, 머리줄을 감싼 `ow-card__open` 버튼이 로빙 tabindex 대상. ↑↓ 로 카드 사이 이동, Tab 으로 그 카드의 다른 버튼(상세 화살표, 결재판 열기·원본 폴더 열기), Enter 실행. 버튼 안에 버튼을 두지 않는다) → 티커는 탭 순서에서 뺀다.
- 캔버스는 키보드로 조작하지 않는다. 같은 정보와 동작이 카드에 다 있다. 캔버스 `<canvas>` 에 `role="img"` 와 `aria-label` (사무실 이름 + 직원 수 + 장애 여부).
- 토스트 영역 `role="status"` `aria-live="polite"`. 장애 시작은 `aria-live="assertive"` 한 번.
- 상태 점은 색만으로 말하지 않는다: 행 `aria-label` 에 "근무 중", "장애" 같은 단어를 넣는다. 레일 항목도 같다.
- 아이콘만 있는 버튼은 모두 `aria-label` (문구는 `phrases.ko.json`). 토글은 `aria-pressed`, 접기는 `aria-expanded`, 스위치는 `role="switch"` `aria-checked`.
- 팝업: `role="dialog"` `aria-modal="true"`, 제목에 `aria-labelledby`, 초점 가두기, Esc 닫기, 닫으면 연 버튼으로 초점 복귀.
- 대비: 글자는 4.5:1 이상 (`--ow-ink-3` 가 최저). 칩 위 글자도 같다.
- 말풍선 DOM 은 `aria-hidden="true"`. 같은 내용이 카드 "지금 하는 일"에 있다.
- 감정 표식은 색·기호만으로 정보를 전달하지 않는다. 확인/추정과 사건 내용은 카드·행적에도 있으며 추정 표식은 점선이다. 장식 표식·일회성 방문 자체에는 초점을 두지 않는다.
- 움직임 줄이기에서는 반복 자세·소품 깜빡임·감정 표식·일회성 방문을 재생하지 않고 현재 상태와 글자를 보인다. 사무실 전환·숨김 복귀 때 생략한 연출을 몰아서 재생하지 않는다.
- 로딩 화면: 단계 목록 `aria-live="polite"`. 아무 키 건너뛰기는 Tab·Shift 같은 보조 키를 제외한다.

## 11. 엣지 케이스

- **직원이 많을 때**: 개발실 6 → 임시 책상 4 → "+n" 배지 + "만석" (겹쳐 앉히지 않는다). 종료한 서브는 10분 뒤 퇴근해 캔버스에서 빠지고 카드는 "퇴근 n" 묶음에 접힌다. 카드는 목록 스크롤. 중소기업 팀장석 4 → 간이 2 → 카드만.
- **사무실이 많을 때**: 사이드바 목록만 스크롤 (간판·바닥 고정). 동 머리글로 접기.
- **긴 이름**: 폴더 이름, 세션 제목, 거래처 상호는 모두 말줄임. 말풍선 최대 너비 240px.
- **모델을 모름**: 모델 칩 "모델 모름", 직급은 사원 ([CONTRACTS C8](../docs/CONTRACTS.md#c8)).
- **컨텍스트 창을 모름**: 눈금 숫자 뒤 "?", 화분 옆 `?` 배지 (DOM, 2px 테두리 정사각형 16).
- **결과 미확인**: 카드 점선 칩 + "결과 확인 불가: …". 신호등·전광판·트럭은 바꾸지 않는다.
- **WSL 꺼짐·지연**: 로딩 "소등" 줄, 사이드바 점선 테, 캔버스 통신 지연 구름.
- **창이 최소 크기보다 작을 때**: 480 시안처럼 패닝 + 미니맵. 어떤 크기에서도 가로 스크롤바가 생기면 안 된다.
